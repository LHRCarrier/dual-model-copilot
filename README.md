# dual-model-copilot

一个给 Codex 用的技能：**让外部模型出方案、本地子代理施工、主代理验收**。

它解决的是同一个问题 —— 让一个模型既出方案又动手，很容易自己说服自己。所以把「出方案」和「动手干」拆到两个不同的认知主体上。

## 三个角色，两个主体

| 角色 | 是谁 | 负责 | 不负责 |
| --- | --- | --- | --- |
| 主代理 | 当前会话的模型 | 摸底、提问、差异对照、拆施工包、**验收与整合** | 不把方向和验收交出去 |
| 方案方 | ChatGPT 网页（应用内置浏览器） | 出方案、找缺口、挑错 | 不接触仓库，不落盘 |
| 施工方 | **子代理** | 改文件、跑测试、如实回报 | 不代替验收；不动写集合之外的东西 |

**两种独立性别混**：子代理给的是**执行隔离**（省上下文、少干扰），**不是判断独立** —— 它和主代理同源，会犯同样的错。判断独立只能靠方案方。所以不能拿子代理当独立审查，它的回报是**待核验的声明**。

## 它真正想防的三件事

1. **外部答卷顺着主代理的预设走** → 用「三栏信息（可核验事实 / 已有决策与约束 / 尚待判断的倾向）+ 三个机械检查（删立场形容词、反事实测试、把建议改成待检验命题）」约束提问。
2. **主代理把「实现符合自己的理解」当成「实现符合需求」** → 施工前**冻结验收条件**；验收时**无提示审查 → 自己重跑 → 验反例 → 三态结论**（已验证 / 未验证 / 有条件通过）。
3. **新会话继承上一会话的叙事，而不是事实** → 任务目录必须落盘四类信息：任务基线、需求→决策→实现→验证映射、执行记录、决策与假设登记。

## 装法

把整个目录放进 Codex 的 skills 目录即可：

```
~/.codex/skills/dual-model-copilot/          # 或 $CODEX_HOME/skills/dual-model-copilot/
```

技能靠 `SKILL.md` 的 frontmatter（`name` / `description`）被匹配加载，不需要额外注册。

## 目录

| 文件 | 作用 |
| --- | --- |
| `SKILL.md` | 主文件：角色 / 路由决策表 / 摸底 / 提问 / 差异对照 / 拆包派发与验收 / 追问与循环上限 / 任务目录与接续 / 安全边界 / 报告 |
| `references/browser-capture.md` | 用应用内置浏览器读回方案方的动作序列，含 8 个实测坑 |
| `scripts/consult-agent.mjs` | 想换模型施工时走 `codex exec` 的外部通道 |
| `scripts/consult-ccswitch.mjs` | 方案方不可用时的文字智囊（**与主代理同源，不能当独立审查**） |
| `agents/openai.yaml` | 界面元数据 |

## 什么时候该用它

- 跨文件功能、架构取舍、疑难 Bug、安全 / 数据一致性审查 → **用**
- 改一两个文件、低风险、可逆 → **不用**，主代理自己改更快

## 前置条件

- 方案方需要一个**已登录的 ChatGPT 网页**，走应用内置浏览器（脚本不代填账号密码，也不该代填）。
- `consult-ccswitch.mjs` 需要一个本地兼容 OpenAI 接口的代理，默认 `http://127.0.0.1:15721/v1`，可用 `BRIDGE_LLM_BASE` / `BRIDGE_LLM_KEY` 覆盖。

## 已知边界（如实写在这里）

- 这套流程**只在极少量真实任务上跑过**，最近一次是真业务任务（产测接口，七轮）。这不是「已证明有效」，只是「还没被发现失效」。
- 外部方案**不是施工指令**，主代理的判断**不是证据**，子代理的报告**不是验收事实**，测试通过**也不是完整验收**。
- 它**不**提供外部施工服务，也不需要：施工在本地子代理里完成。
